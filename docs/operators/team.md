# Your team

Anyone who helps run your servers can have their own sign-in, with only what they need: a moderator to handle appeals and reports, an admin to run the servers, a viewer to look. You manage the team under **Team** in the portal.

## The roles

|                                                                | Owner |            Admin            | Moderator | Viewer |
| -------------------------------------------------------------- | :---: | :-------------------------: | :-------: | :----: |
| See servers, ban list, appeals, reports, dashboards, live view |   ✓   |              ✓              |     ✓     |   ✓    |
| **Answer appeals**                                             |   ✓   |              ✓              |     ✓     |        |
| **Handle reports** (dismiss, or act on)                        |   ✓   |              ✓              |     ✓     |        |
| **Add a ban by hand, lift an action**                          |   ✓   |              ✓              |     ✓     |        |
| Add and rename servers, change a server's rules                |   ✓   |              ✓              |           |        |
| API keys and webhooks                                          |   ✓   |              ✓              |           |        |
| Invite and manage the team                                     |   ✓   | moderators and viewers only |           |        |
| Remove a server                                                |   ✓   |                             |           |        |
| Plan and billing, accept the agreement                         |   ✓   |                             |           |        |

- A **moderator** or a **viewer** can be limited to **some of your servers**. They then see, and can act on, only those: the lists, the dashboards, the live view and the emails all follow it, and another server simply does not exist for them. Owners and admins always see every server.
- An **owner** can do everything, including inviting another owner. There is always at least one.
- The old read-only "member" is now a **viewer**.

## Inviting someone

1. Under **Team**, choose **Invite**, enter their email address, a role and, for a moderator or viewer, which servers.
2. They get an email with a link, good for 14 days. It lets them **choose a password**, and confirms their address. You can send it again after an hour.
3. They sign in and see only what their role allows. Until they follow the link they cannot sign in, but they do take up a place on your team. An invitation nobody follows for 14 days lapses, and frees the place.

One address can belong to only one team. If you invite an address that already has a ServerGuardian account, you get the same answer as for any address, and that person is emailed to say someone tried (nothing changes, and they take no place on your team): if they do not show up as invited, ask them to use another address. This keeps invitations from being used to find out who has an account. A person you removed can be invited again.

## Changing and removing

- **Change** someone's role or servers at any time; it applies the next time they do anything.
- **Remove** someone and they are signed out straight away, everywhere.
- Nobody can change or remove **themselves**, and an admin cannot touch an owner or another admin.

## Appeals and emails

When a player appeals, the email goes to your owners, your admins and the moderators who may work on that server. Any of them who may answer can; the first answer is the one that counts.

## Limits

How many people a team can hold depends on your plan; the Team page shows yours. Pending invitations count. You can send a limited number of new invitations an hour. These are first guesses and may change.

## Keep it safe

- Give people the **least** they need. A moderator rarely needs more than a moderator.
- **Turn on two-step sign-in** for owners and admins, who can create keys and change rules. Inviting, changing and removing people asks for it too, as creating a key does.
- Every change to the team (an invitation, a new role, a removal) is recorded in ServerGuardian's audit log.
